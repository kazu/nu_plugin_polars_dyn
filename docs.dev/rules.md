# ローカルルール

この repo で作業するときの規約。1 ルール 1 項目で、理由が要るものだけ短く添える。
Rust の書き方は [rust_style.md](./rust_style.md)、設計の合意は [agreements.md](./agreements.md)。
ここにある項目は後で全プロジェクト共通に昇格させることがある。

1. 今の要求に無い機能・引数・抽象・設定は作らない(YAGNI)。「後で要りそう」は理由に
   ならない。要ったときに足す方が、当たらない予測で作ったものを消すより安い。設計で落とした
   候補は「採らなかった案」として 1 行残し、無かったことにはしない。
2. コメントは最小限。書くのは (a) 契約と例 = rustdoc、(b) `unsafe` の `// SAFETY:`、
   (c) 未対応の不具合・制約を示すマーカー、の 3 種だけ。コードが何をしているかの言い直し、
   経緯、消した commit message の写しは書かない。「なぜこの形か」が要るなら、それは rustdoc の
   契約か `docs.dev/` の設計文書に置く。
3. ガード志向で書く。関数の先頭で入力の前提を検査して早期 `return` し、正常系は字下げ無しで
   最後に 1 本書く。前提の検査を本体の `if` / `match` の中に散らさない。ガードで弾く条件は、
   その関数の契約(rustdoc)に書いてあることと一致させる。
4. ワークアラウンドを本流に埋め込まない。ワークアラウンドとは、入力か出力の保証を崩す処理、
   ライブラリの不具合の回避、特定の値の特別扱いのこと。書く前にまず設計と自分の理解を疑い、
   それでも要るなら (a) 何を回避しているかが名前で分かる**別関数**に分離し、(b) その rustdoc に
   **崩れる保証と理由**を書き、(c) 呼び出しは 1 箇所にする。本流の関数に `if` で継ぎ足さない。
   分離できない形なら書かずに kazu に聞く。
