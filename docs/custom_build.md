# Building a binary with your own scan source

How to add a scheme, a compression or a format `polars_dyn open` can read. A scan source is
compiled into the plugin, so the binary is rebuilt — but the only code you write is the scan source
crate. The cargo project and the `main.rs` are generated by `nu-polars-dyn-build`.

This document is the sequence of commands. Why it is shaped this way is in
`docs.dev/custom_build.md` (Japanese).

## 1. Get the builder

`nu-polars-dyn-build` lives in the same crate as the plugin. Build it from the repository:

```nu
cd <this repo>
$env.CARGO_TARGET_DIR = ($env.HOME | path join ".cargo" "target")
cargo build --release --bin nu-polars-dyn-build
```

That leaves `~/.cargo/target/release/nu-polars-dyn-build`.

Once the plugin is published, `cargo install nu_plugin_polars_dyn --locked` installs the builder as
well, next to the plugin in `~/.cargo/bin/`. **It is not published yet.**

## 2. Write the scan source crate

A scan source crate is a Rust lib crate. It must provide two things, and nothing else is looked
at:

1. one or more types that implement the trait `nu_plugin_polars::scan::ScanSource`;
2. one public function `scan_sources()` that returns those types.

### 2.1 The trait `ScanSource`

Defined in `src/scan/mod.rs` of `nu_plugin_polars_dyn`, reachable as
`nu_plugin_polars::scan::ScanSource`.

```rust
pub trait ScanSource: Send + Sync {
    fn name(&self) -> &'static str;
    fn suffixes(&self) -> &'static [&'static str];
    fn schemes(&self) -> &'static [&'static str] { &[] }
    fn open(&self, url: &str, opts: &[u8]) -> PolarsResult<Arc<dyn ReadAt>>;      // default: error
    fn wrap(&self, source: Arc<dyn ReadAt>, opts: &[u8]) -> PolarsResult<Arc<dyn ReadAt>>; // default: error
    fn scan(&self, source: Arc<dyn ReadAt>, opts: &[u8]) -> PolarsResult<LazyFrame>;     // default: error
}
```

A source string is resolved into a **chain** of these (the rules are under
[`polars_dyn open`](./cli.md#polars_dyn-open)): the scheme picks the first source, which is asked to
`open`; each suffix picks one more, and every one but the last is asked to `wrap`, the last to
`scan`. A source implements the one or two of the three it does and leaves the rest at their
defaults. It never learns what comes before or after it: `open` gets the string, `wrap` and `scan`
get bytes, and what those bytes are — a local file, an sftp handle, a decompressed stream — is
not its business. That is what lets an `ssh` you write feed a `seek-zst` somebody else wrote feed
the built-in `ndjson`.

The implementing type is a `'static` value, usually a unit struct; the plugin holds a
`&'static dyn ScanSource` to it for the life of the process and calls it from any thread, hence
`Send + Sync`.

#### `name`

- Returns the registered name. `--format` selects the source by it, the `--opts` record is keyed by
  it, and the errors for an unknown source list it.
- Requirements: unique across every source in the binary, including the built-ins `file`, `parquet`,
  `csv`, `ipc` and `ndjson`. A duplicate makes the plugin exit at start with
  `scan source name `<name>` is registered twice`.

#### `suffixes`

- Returns the suffixes by which the source is put into a chain when `--format` is absent: the
  longest registered suffix ending the source string is stripped and this source appended, and the
  stripping repeats on what is left.
- Requirements: each suffix starts with `.`, and no suffix is claimed by two sources in the binary
  (`scan sources `<a>` and `<b>` both claim the suffix `<s>``). A suffix names one step, so
  `.seek.zst` is right and `.jsonl.seek.zst` is wrong: the latter would take the place of two
  steps and stop `ndjson` from being picked. A source with an empty list can only be reached
  through `--format` or its scheme.

#### `schemes`

- Returns the URL schemes this source opens, e.g. `["ssh"]`. A source string
  `<scheme>://...` puts this source first in the chain and calls its `open`.
- Requirements: no scheme claimed by two sources (`... both claim the scheme `<s>``). `file` is
  taken by the built-in. Leave the default empty list for a source that opens nothing.

#### `open`

- Called once per `polars_dyn open` on the first source of the chain, with the whole source string
  including the scheme. Returns the bytes for the rest of the chain to read.
- `url`: the source string as typed, e.g. `ssh://user@host/var/log/x.jsonl.seek.zst`. The suffixes
  are still on it; parse what you need and ignore the rest.
- `opts`: the value under this source's name in `--opts`, encoded as JSON, or an empty slice.
- Requirements: return a handle that can be read by offset from several threads at once (see
  [2.2](#22-the-trait-readat)). Return `Err` rather than panic for anything the input or the options
  can cause. `ssh-scan/src/lib.rs` in this repository opens over sftp.

#### `wrap`

- Called on a source in the middle of the chain: bytes in, bytes out. A decompressor, a container
  format, a decryptor.
- Requirements: the returned handle reads by offset into the *transformed* bytes, and its `len` is
  their length. Reading ahead of what was asked is fine; caching is yours to decide.
  `seekzstdsep-scan/src/seek_zst.rs` wraps a seekable zstd file into the bytes it decompresses to.

#### `scan`

- Called on the last source of the chain. Builds the `LazyFrame` and returns it. Nothing is read
  yet unless the source needs to (a schema, say); the rows are read when the frame is collected.
- `source`: the bytes to read. The source does not learn the path, nor whether the bytes came
  through a `wrap`.
- `opts`: as for `open`. `parse_opts` turns it into a `serde_json::Map`, and `overlay_opts` lays it
  over a serde struct of defaults and refuses unknown keys. `no_opts` refuses everything, for a
  source that takes nothing.
- Requirements: return `Err` rather than panic. The error text is shown to the user as
  `<name> scan error`, pointing at the source argument. Do not collect the frame.

### 2.2 The trait `ReadAt`

`nu_plugin_polars::scan::ReadAt`, the handle that passes between sources.

```rust
pub trait ReadAt: Send + Sync {
    fn read_at(&self, offset: u64, buf: &mut [u8]) -> io::Result<usize>;
    fn len(&self) -> io::Result<u64>;
}
```

- `read_at` reads from `offset` into `buf` and returns how many bytes were read. Fewer than
  `buf.len()` can come back before the end, and `0` means `offset` is at or past the end. Every
  call names its offset and takes `&self`, so one handle can be read from several threads at once
  without a position to share; a handle that has to serialize its reads does so with a `Mutex`
  inside.
- `len` is the length in bytes.
- Only random-access sources are handed out; a pipe or a socket never reaches a scan source.
- `read_fully` keeps calling `read_at` until `buf` is full or the source ends.
- A library that wants `Read + Seek` is given `ReadAtCursor`: a struct holding the
  `Arc<dyn ReadAt>` and its own position, one per thread.

### 2.3 The entry point `scan_sources`

```rust
pub fn scan_sources() -> &'static [&'static dyn nu_plugin_polars::scan::ScanSource];
```

- Requirements: `pub`, at the crate root, exactly this signature. `nu-polars-dyn-build` writes a
  `main.rs` that calls `<crate>::scan_sources()` for every crate it was given and hands the
  concatenation to the plugin. A crate without it fails to compile the generated project
  (`cannot find function scan_sources in crate ...`); nothing checks it earlier.
- The slice and the sources it points to are `'static`: `&[&MyFormat]` with unit structs, or
  `static` items.

### 2.4 The manifest

An ordinary lib crate that depends on `nu_plugin_polars_dyn` (its lib is named
`nu_plugin_polars`) and on polars at the same version the plugin uses.

```toml
[dependencies]
nu_plugin_polars_dyn = "0.2"
polars = "=0.55.2"
```

### 2.5 Example

```rust
use std::sync::Arc;

use nu_plugin_polars::scan::{ReadAt, ScanSource, parse_opts};
use polars::prelude::{LazyFrame, PolarsResult};

pub fn scan_sources() -> &'static [&'static dyn ScanSource] {
    &[&MyFormat]
}

struct MyFormat;

impl ScanSource for MyFormat {
    fn name(&self) -> &'static str {
        "myformat"
    }

    fn suffixes(&self) -> &'static [&'static str] {
        &[".myfmt"]
    }

    fn scan(&self, source: Arc<dyn ReadAt>, opts: &[u8]) -> PolarsResult<LazyFrame> {
        let opts = parse_opts(opts)?; // serde_json::Map
        todo!()
    }
}
```

A minimal working implementation is `tests/rows_scan/src/lib.rs` in this repository. The three
kinds of step each have a real one here: `ssh-scan/` opens, `seekzstdsep-scan/` wraps, and
`logfmt-scan/` in [polars-logfmt](https://github.com/kazu/polars-logfmt) scans a real format.

## 3. Build

To compile in `seekzstdsep-scan` and `ssh-scan` from this repository and `logfmt-scan` from a
checkout of polars-logfmt, so that `.seek.zst`, `ssh://` and `.logfmt` all work, in any
combination:

```nu
nu-polars-dyn-build seekzstdsep_scan ssh_scan logfmt_scan --path seekzstdsep_scan=/path/to/nu_plugin_polars_dyn/seekzstdsep-scan --path ssh_scan=/path/to/nu_plugin_polars_dyn/ssh-scan --path logfmt_scan=/path/to/polars-logfmt/logfmt-scan --out ~/bin
```

The general form is:

```nu
nu-polars-dyn-build my_scan_source
```

`nu_plugin_polars_dyn` appears in the current directory. The positional arguments are crates.io
crate names, without a version. If you are building against a version that has no tag yet, read the
section below as well. A crate that is not published needs its source spelled out:

```nu
nu-polars-dyn-build my_scan_source --path my_scan_source=../my_scan_source
nu-polars-dyn-build my_scan_source --git my_scan_source=https://example.com/my_scan_source
```

Any number of crates can be listed:

```nu
nu-polars-dyn-build a b c --path a=../a --git b=https://example.com/b
```

| option | meaning |
|---|---|
| `--path <name>=<dir>` | take that crate from a directory |
| `--git <name>=<url>` | take that crate from git |
| `--out <dir>` | where to put the binary. The default is the current directory |
| `--debug` | debug build. The default is release |

cargo's output passes straight through, a failure returns cargo's exit code, and the generated
project is kept and its path printed to stderr. Setting `CARGO_TARGET_DIR` shortens every build
after the first.

### Building against a version with no tag

The generated project takes `nu_plugin_polars_dyn` from the repository the builder itself was built
from, at the tag for its own version. **A version whose tag has not been pushed cannot be
resolved.** Point it at your checkout instead:

```nu
$env.NU_POLARS_DYN_SOURCE = "/path/to/nu_plugin_polars_dyn"
nu-polars-dyn-build my_scan_source --path my_scan_source=../my_scan_source
```

Every released version has its tag pushed, so this is only needed for an unreleased checkout.

## 4. Register it and use it

```nu
plugin add ./nu_plugin_polars_dyn
plugin use polars_dyn
polars_dyn open data.myfmt | polars_dyn collect
polars_dyn open data.myfmt --opts {myformat: {my_option: 10}} | polars_dyn collect
polars_dyn open data.myfmt.seek.zst | polars_dyn collect          # with seekzstdsep_scan built in
polars_dyn open ssh://host/data.myfmt | polars_dyn collect        # with ssh_scan built in
polars_dyn open data.csv | polars_dyn collect                     # the built-ins still work
```

The binary **replaces** the standard `nu_plugin_polars_dyn`, and the built-in `file`, parquet, csv,
ipc and ndjson keep working.

`plugin add` stores the signature as it was at registration time, so run it again whenever you
replace the binary. To try one out without touching the registry:

```nu
nu --plugins [./nu_plugin_polars_dyn] -c "polars_dyn open data.myfmt | polars_dyn collect"
```

## The limits you will hit

A `scan` of your own is usually a polars `AnonymousScan`, as the built-in csv and ndjson are. When
it is:

- **`polars_dyn collect --streaming` cannot be used.** polars-stream drops `AnonymousScan` on a
  `todo!`, which comes back as an error. There is no fallback to the in-memory engine.
- **A `slice` with an offset does not reach `scan`.** `polars_dyn slice 1000 10` reads everything
  and lets the plan take 10 rows. **Nothing detects this, so there is no warning.**
  `polars_dyn slice 0 10` does reach it.
- **The `n_rows` that `scan` receives applies before the predicate.** It counts rows of the file,
  so applying it the other way round answers wrongly without saying so.
- **A predicate you cannot evaluate may arrive.** The dynamic bounds of `sort` + `slice` come
  through in the optimizer's own representation, and handing one to `LazyFrame::filter` takes the
  process down. Split the `and` into its terms and drop only that term — dropping it is correct,
  because `sort` carries its own slice.

The plugin's own chunked reader (`src/scan/chunked.rs`) handles all four for csv and ndjson; a text
format of your own can be written the same way.
